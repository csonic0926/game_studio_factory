# Studio v2 capability

Process: `factory_core/docs/WORKFLOW.md`; semantic ownership stays here.
Start with inspect/context. Read the current Product authority lifecycle before
trusting old code/theses/baselines. An archived direction cannot reactivate itself.
Diagnose the actual baseline pressure. Research same-type, cross-genre and
non-game mechanisms when needed; no source/extraction quota or fabricated demand.

Author one complete causal system and its minimum **cycle-complete** unit.
Decision -> commitment -> resolution -> reward -> reinvestment -> return must
close; reward changes a visible state read by the next decision. Show two laps
with materially different second work. Bound breadth/fidelity, never remove a
load-bearing edge or one half of a coupled product promise. Gamification still
needs this loop even when combat/challenge is a non-goal.

The package includes the full objective, graph, interaction contract, active
project Card standard and required compositions. Existing graph and interaction
validators are reused by `gameplay/v2.py`, with Git provenance retained and v2
content validity. Both complete-design reviews subsume generic semantic,
project-standard, final-Card, player-surface design and two-way projection
obligations; their role mapping is explicit in `factory_core/rule_map.json`.
Do not manufacture old review identities/artifacts to make a v2 package pass v1.
Human view is exact design excerpts plus references. USER rules on that view;
production plans only add execution details. Keep pending/rejected legacy Cards
historical until an explicit new design/ruling exists.

Production integration must preserve state ownership, simultaneous input/UI
attention constraints and prior gameplay. Godot adapter technical evidence is
EVIDENCE_ONLY. Runtime evidence/acceptance remains governed by
`PLAYER_FACING_GAMEPLAY_EVIDENCE_GATE.md` and `BASELINE_ADMISSION_WORKFLOW.md`.
Independent blind observation and informed comparison, exact-build human
playtest, predecessor regression and blocking-gap clearance are not merged into
the two design reviews. Never present a runnable demo as Studio delivery.

The v2 design bridge is consumed by the existing Gameplay plan CLI. Runtime
`factory_gameplay_acceptance_input.v2` is dispatched by `studio/baseline.py` to
`studio/v2.py`: it validates the exact evidence-ready checkpoint, graph, two-lap
observation and the unchanged player-surface blind/comparison chain. Existing
v4 acceptance reviews still require the exact USER playtest token. Existing
baseline admission still owns complete reconstruction or predecessor promotion,
full regression, runtime cleanliness, blocking gaps and immutable outputs.
No old Card, register entry or review identity is fabricated for this bridge.
