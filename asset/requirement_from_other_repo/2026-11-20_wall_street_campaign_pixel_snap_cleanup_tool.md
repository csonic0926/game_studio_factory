## User-facing need

AI-generated "pixel art" is not real pixel art: the grid is uneven, edges are
anti-aliased, and the palette has hundreds of near-duplicate colours. Every game
repo that wants pixel art has to clean it up, and today the only good tool for
that lives inside one game repo, so other repos either do not know it exists or
write a worse ad-hoc version (this session first wrote a PIL box-downscale +
median-cut script before the user pointed at the existing tool).

The user wants the asset factory to own this as a supported, documented tool
that any caller repo can find and run.

## Factory-side change requested

Bring the existing pixel-snap tool into `game_asset_factory` as a supported

## Asset / workflow details

- Asset family / workflow name: pixel-snap cleanup (post-processing, provider-independent)
- Source tool: `$UPSTREAM_ROOT/scripts/pixel_snap.js`
  (733 lines, Node + `sharp`; exports `pixelSnap(input, output, options)`).
  It follows Gerstner et al. 2012, "Pixelated Image Abstraction": CIELAB colour
  distance, each output pixel as a constrained superpixel, palette built by
  splitting high-error clusters, alpha handled as its own class with fringe
  cleanup.
- Companions in the same folder: `pixel_snap_animated.js` (GIF / animated WebP
  wrapper), `pixel_snap_compare.js` (side-by-side comparison). Include the
  animated wrapper if it is cheap; the compare script is optional.
- Variants or states: profiles `conservative` (scale 2, 24–42 colours),
  `balanced` (scale 3, 20–36), `chunky` (scale 4, 18–32), `auto`; `--scale N`
  overrides the grid size.
- Target canvas size: the tool writes the result back at the source size with
  nearest-neighbour enlargement. Please also add an option to write the
  true-grid image (source size ÷ scale), because web and engine callers often
  want the small image and scale it themselves.
- Anchor / pivot rule: unchanged from the input.
- Transparency/background rule: input alpha is preserved and snapped
  (`ALPHA_THRESHOLD = 24`, fringe cleanup). Opaque backdrops stay opaque.
- Target project folder: caller-chosen output path; the tool must not write
  into a caller repo unless given the path.
- Required metadata fields: the tool already returns `profile`, `targetScale`,
  `gridW`, `gridH`, `finalColors`, `sourceUniqueColors`; keep them and print or
  save them so a caller can record what was done.
- Provider/model preference: none. No image model is called.
- Provider/model constraints: none.
