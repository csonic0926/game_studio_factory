# Player-text clarity

Resolve the explicit target project and this skill's real Factory source root.
Do not initialize, migrate, relink or install anything merely to use this skill.
Read `player_text/WORKFLOW.md`; use `player_text/CONTRACT.md` for the CLI and
evidence formats. All project artifacts go to the target, never Factory.

Inventory ALL player-facing surfaces/locales for a whole-game request, or an
honestly bounded CHANGED scope. Dialogue, narration, functional copy, baked-in
text, speech and generated variants all count. An unsupported source format
requires an audited export and exact actual-source/runtime binding, not omission.

Prepare before-text, treat every item (retain or repair), and seal actual output.
Keep the content owner's facts, conditions, canon, voice, knowledge boundaries,
numbers, placeholders, markup and authority. Do not turn narration into speech
or obey brevity at the expense of natural grammar. Material meaning changes
return to the owning design decision; this workflow grants no such permission.

Obtain a fresh non-author first reading using ONLY `reader-packet`, then a
distinct informed meaning/coverage/presentation backcheck. Work in coherent
batches, not one agent per string. Use actual isolated executions; if unavailable,
save incomplete work and report the missing review, never invent identities or
PASS records. Existing Story dialogue production remains separately isolated;
its repaired text feeds this workflow without a redundant compulsory rewrite.

Run `check`, then return the exact receipt and scope to the caller. Any later
text/context/presentation change requires renewed evidence. An AI reading and a
valid receipt are not human comprehension, creative approval or game acceptance.
