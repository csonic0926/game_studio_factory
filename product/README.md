# Product Factory

Why could this whole offer be worthwhile for its intended buyer, and does the
experienced game actually earn that offer? Product is the peer value specialist
from project initialization through whole-product judgment, complementary to
Idea's commissioned direction and Studio's playable-baseline lifecycle.

Start at [the caller landing](docs/AI_CALLER_LANDING.md) or the
[product-factory skill](skills/product-factory/SKILL.md).

- [Joint project initialization](docs/PROJECT_INITIALIZATION_WORKFLOW.md):
  `setup.py init --game-repo <GAME>` establishes routing, missing Idea work and
  nonbinding Product intent. Continue beyond the seed into real hypotheses,
  unknowns and the smallest useful value experiment. `product.py start` adds only
  the intent to an existing game; neither entry requires workflow migration
- [Value assessment](docs/VALUE_ASSESSMENT_WORKFLOW.md): encounter the actual
  value-bearing experience and make a coherent scoped judgment. `product.py`
  validates provenance, independent-review bindings and exact claim scope; it
  does not calculate value

Intent is not authority, actual experience or a value result. Existing commission,
activation/archive, design approval, actual-play and baseline gates retain their
meaning. Mandatory whole-product review remains at existing stopping/value-claim
boundaries; early learning and authorized production need no commercial PASS.
There are no points, feature quotas, minimum hours, mandatory replay loops, fixed
staged-call protocol or automatic commercial PASSes.
